# badblocks-victoria 挂载状态误判修复说明（0.3.2 → 0.3.4）

## 问题现象

已挂载的硬盘在应用里显示为"未挂载"。

## 根因

物理盘本身通常没有挂载点，真正的挂载发生在它的上层：分区、md RAID 阵列、dm/LVM 卷、或 ZFS 池。
旧版 `/api/disks` 只读取该物理盘节点自身的 `MOUNTPOINT` 字段，因此几乎所有盘都被判为未挂载。
另外 ZFS 池成员盘既不出现在 lsblk 挂载点里，也不出现在 `/sys/block/*/holders` 中，属于第二处漏判。

## 修复内容

| 位置 | 改动 |
|---|---|
| `src/main.go` `collectDiskMounts` | 沿 lsblk 子树递归汇总所有层级的 `MOUNTPOINTS`/`MOUNTPOINT` 到物理盘；同时识别 `raid*/lvm/crypt/zfs_member/mpath` 层，输出 holders 标记 |
| `src/main.go` `zfsVolumeMounts` | 新增：读 `/proc/mounts` 取 fstype=zfs 的池/数据集挂载点，再通过 `zpool status -P` 反查成员盘，映射为"成员盘 → 池挂载点" |
| `src/main.go` `zpoolPath` | 应用运行时 PATH 通常不含 `/sbin`、`/usr/sbin`，改为先 `LookPath` 再探测常见绝对路径，避免 zpool 找不到导致 ZFS 盘漏判 |
| `src/main.go` `diskBaseName` | 分区名归一化（`sdc1→sdc`、`nvme0n1p2→nvme0n1`），保证 ZFS 反查能命中物理盘名 |
| `src/repair.go` `inspectDiskUsage` | remap 前置校验同步使用子树聚合 + ZFS 回退，避免"已挂载盘"被误判为可做写测试 |
| `ui/app.js` | 列表新增挂载摘要：显示"已挂载 /volX 等 N 处"，未挂载显示"未挂载"；挂载路径完整展示 |
